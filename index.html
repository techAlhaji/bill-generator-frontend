System Architecture

Multi-Repository System Topology

The workspace strictly maintains three decoupled repositories with independent lifecycles, test suites, and deployment pipelines.

Independent Repository Workspace Invariant

The root directory remains an uninitialized non-git container workspace to preserve clean commit histories and individual GitHub Actions CI/CD pipelines across the three domain modules.

🖥️ Presentation Layer

`bill-generator-frontend` provides the responsive merchant portal, CRM client index, real-time metrics, printable CSS invoices, and public capability URLs (`/pay/[token]`).

⚙️ Execution & Verification Layer

`bill-generator-backend` manages authentication (JWT + SEP-10), ACID invoice state persistence, vector PDF compilation, and independent Horizon / RPC transaction verification.

⛓️ On-Chain Settlement Anchor

`bill-generator-contracts` registers 32-byte immutable SHA-256 digests of canonical invoices, coordinates SEP-41 token settlements, and records reconciled Classic payments.

Security Architecture

Zero-Trust Payment Settlement

Client frontend environments are treated as untrusted runtime contexts. Invoices never transition to PAID based on UI signals.

  • Horizon Transaction Inspection: For Stellar Classic payments, backend inspects the ledger transaction, verifies successful status, checks destination address, verifies exact asset code & issuer, and enforces strict matching with the unique invoice memo string.
  • Soroban RPC Event Verification: For contract payments, the backend parses the contract execution results via `getTransaction`, confirming invocation of `pay_invoice` on the `InvoiceRegistry` and checking the canonical 32-byte `invoice_id`.
  • Replay Attack Prevention: All verified transaction hashes are written to the PostgreSQL `payments` table under a strict database unique constraint, preventing double-spending or hash re-use.
Financial Reliability

Zero-Float Integer Arithmetic

Eliminating IEEE 754 floating-point inaccuracies through standardized fixed-point scaling.

Storage Data Models

Rust (contracts/invoice_registry/src/types.rs) 
#[contracttype]
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct InvoiceRecord {
    pub issuer: Address,          // Merchant receiving address
    pub amount: i128,             // Amount in token base minor units
    pub token: Address,           // Token contract address (or SAC address)
    pub content_hash: BytesN<32>, // Canonical SHA-256 hash of invoice contents
    pub status: InvoiceStatus,    // Unpaid (0), Paid (1), Cancelled (2)
    pub payment_ref: BytesN<32>,  // Transaction hash or payment receipt
    pub settled_at: u64,          // Ledger timestamp of settlement
}

#[contracttype]
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
#[repr(u32)]
pub enum InvoiceStatus {
    Unpaid = 0,
    Paid = 1,
    Cancelled = 2,
}

Contract Public Interface

Method Signature Authorization Description
initialize(admin: Address) System Admin Initializes contract state and assigns the administrative address. Emits initialized event.
register_invoice(issuer, invoice_id, amount, token, content_hash) issuer.require_auth() Anchors a new invoice commitment on-chain. Emits invoice_registered event.
pay_invoice(payer, invoice_id) payer.require_auth() Transfers SEP-41 token atomically from payer to issuer and sets status to Paid. Emits invoice_paid event.
record_direct_settlement(issuer, invoice_id, tx_ref) issuer.require_auth() Reconciles an on-chain commitment with an off-chain/L1 Classic payment receipt.
get_invoice(invoice_id) Public Read Returns Option<InvoiceRecord> for the given 32-byte identifier.

Repository: bill-generator-backend

Backend REST Engine & Verification Pipeline

Production-grade Fastify TypeScript backend with Prisma ORM, SEP-10 challenge authentication, and OpenAPI 3.0 specification.

🔐 Dual Authentication Mode

Supports both conventional JWT credentials (email/password) and Web3 non-custodial SEP-10 wallet challenge-response signing for frictionless merchant access.

📄 Vector PDF Invoicing Engine

Server-side streaming PDF generation using PDFKit, rendering print-ready commercial invoices with embedded Stellar payment QR codes.

🗄️ PostgreSQL ACID Guarantees

Row-level serializable locks prevent invoice duplicate reconciliation. Financial balances stored in native BigInt integer stroops.

Initiates a cryptographic challenge envelope for non-custodial wallet sign-in.

GET /api/v1/invoices Paginated list of merchant invoices with lifecycle filters

Query parameters: page, limit, status (DRAFT, ISSUED, PAID, OVERDUE, CANCELLED), clientId.

POST /api/v1/invoices Creates a new draft commercial invoice with zero-float line items

Validates line items, integer quantities scaled by $10^4$, and basis-points tax computation.

GET /api/v1/public/invoices/:token Unauthenticated capability URL for payer review and checkout

Strips all internal merchant notes and database IDs. Returns payment destination, memo string, asset code, and amount in minor units.

POST /api/v1/public/invoices/:token/verify-payment Zero-trust cryptographic settlement verification on Horizon / Soroban

Verifies transaction hash directly with Horizon or Soroban RPC. Replay attacks are rejected with 409 Conflict.

Payment Verification Engine Flow

Sequence (Horizon / Soroban RPC) 
1. Payer submits transaction hash to /api/v1/public/invoices/:token/verify-payment
2. Idempotency Check: Verify txHash is not previously redeemed in PostgreSQL
3. Row-Level Lock: Acquire SELECT FOR UPDATE on Invoice record
4. Blockchain Verification:
   • STELLAR_CLASSIC: Query Horizon /transactions/:hash & /operations
     Verify recipient == merchantAddress, asset == invoiceAsset, memo == invoiceMemo
   • SOROBAN_TOKEN: Query Soroban RPC getTransaction(:hash)
     Verify contractId == InvoiceRegistry, event topics contain invoice_id
5. State Transition:
   • INSERT payments (status: CONFIRMED)
   • UPDATE invoices (status: PAID, paidAt: now())
   • INSERT audit_logs (action: PAYMENT_CONFIRMED)

Backup, Migration & Recovery Procedures

Documented in detail in bill-generator-backend/docs/BACKUP_MIGRATION_RECOVERY.md:

  • ACID PostgreSQL Snapshots: Nightly pg_dump with level 9 compression and AES-256 GPG encryption.
  • Point-in-Time Recovery (PITR): Continuous WAL archiving for 7-day rollback tolerance.
  • Declarative Migrations: Managed strictly via Prisma migrations with pre-flight dry runs and rollback runbooks.

End-to-End Payment Flow Walkthrough

  1. Merchant Creates Invoice: In frontend wizard, merchant enters line items $\to$ backend stores draft with canonical RFC 8785 JSON hash.
  2. Issuance & Commitment Anchor: Merchant issues invoice $\to$ backend generates capability token $\to$ anchors 32-byte content_hash on Soroban InvoiceRegistry.
  3. Payer Receives Capability Link: Payer navigates to /pay/[token], connects Freighter wallet.
  4. Payment Dispatch: Payer submits transaction to Stellar Horizon (XLM / Classic asset) or executes pay_invoice on Soroban.
  5. Cryptographic Settlement: Backend independently verifies ledger finality, locks invoice state, records payment receipt in PostgreSQL, and updates on-chain registry.
